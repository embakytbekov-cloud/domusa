# ДомUSA — Telegram Mini App

Поиск и размещение жилья (комнаты, посуточная/долгосрочная аренда) в русскоязычных районах США. Каркас MVP на основе дизайн-прототипа.

## Что уже готово

- Все 5 экранов из прототипа: лента объявлений с категориями и рейлами по городам, карточка объявления, избранное, форма размещения объявления, профиль.
- Фильтры (город, цена) — bottom sheet.
- Мягкая авторизация через Telegram ("gate") — как в прототипе: действие (сохранить, забронировать, опубликовать) сразу запрашивает подтверждение профиля через Telegram, без анкеты.
- Интеграция с Telegram WebApp SDK (`@twa-dev/sdk`) — имя/фото пользователя, `ready()`/`expand()`.
- Мок-данные (9 городов/регионов, ~30 объявлений) — точная копия данных из прототипа.
- Слой данных (`src/lib/repo.ts`) уже написан в асинхронном стиле — при подключении Supabase меняются только его функции, экраны переписывать не нужно.
- Готовая SQL-схема и Edge Function для Supabase (см. ниже) — пока не подключены, приложение работает полностью на моках.
- Сборка (`npm run build`) проходит без ошибок TypeScript.

## Чего пока нет (следующие шаги)

- Реального бэкенда — все данные сбрасываются при перезагрузке страницы (стейт в памяти).
- Загрузки настоящих фото (в форме размещения — просто заглушки-слоты).
- Оплаты $3 за второе и последующие объявления (сейчас это просто текст).
- Карты (в карточке объявления — статичная заглушка, как и в прототипе).

## Запуск локально

Нужен Node.js 20+ (у вас уже установлен — на Windows это можно проверить командой `node -v` в терминале).

```bash
npm install
npm run dev
```

Откроется адрес вида `http://localhost:5173` — откройте его в браузере. Приложение полностью рабочее и без Telegram (используется тестовый пользователь "Алексей Ковалёв").

## Структура проекта

```
src/
  types/listing.ts     — типы данных (объявление, пользователь, форма)
  data/                — мок-данные и константы (города, категории, цены)
  store/appStore.ts    — состояние приложения (Zustand): навигация, фильтры,
                          избранное, форма, gate-модалка, тосты
  lib/
    repo.ts            — доступ к данным (сейчас моки, потом — Supabase)
    telegram.ts        — обёртка над Telegram WebApp SDK
    supabase.ts        — клиент Supabase (создаётся только если задан .env)
    auth.ts            — привязка Telegram-профиля через Edge Function
    filters.ts          — логика фильтрации объявлений
  components/          — переиспользуемые блоки (карточка, чипы, модалки, таб-бар)
  screens/             — 5 экранов приложения
supabase/
  schema.sql           — таблицы, RLS-политики, Storage bucket для фото
  functions/telegram-link/ — Edge Function проверки подписи Telegram
```

## Как открыть приложение внутри Telegram (тестирование)

Telegram Mini App должен быть доступен по HTTPS-адресу. Для локальной разработки проще всего пробросить туннель:

1. Установите [ngrok](https://ngrok.com/download) (или используйте `cloudflared tunnel`).
2. Запустите `npm run dev`, затем в отдельном терминале: `ngrok http 5173`.
3. Скопируйте выданный `https://...ngrok-free.app` адрес.
4. В Telegram откройте [@BotFather](https://t.me/BotFather) → создайте бота (`/newbot`), если ещё нет → `/mybots` → выберите бота → **Bot Settings → Menu Button** (или `/newapp` для полноценного Mini App) → укажите URL из шага 3.
5. Откройте бота в Telegram и нажмите кнопку меню — приложение откроется внутри Telegram, и `window.Telegram.WebApp` будет доступен по-настоящему (подставится ваше реальное имя и фото).

## Деплой в продакшен

Проще всего — [Vercel](https://vercel.com) или [Netlify](https://netlify.com): импортируете репозиторий, команда сборки `npm run build`, папка публикации `dist`. После деплоя обновите URL в @BotFather на постоянный адрес (вместо ngrok).

## Подключение Supabase (когда будете готовы)

1. Создайте проект на [supabase.com](https://supabase.com).
2. Откройте **SQL Editor** → вставьте содержимое `supabase/schema.sql` → Run. Это создаст таблицы `profiles`, `listings`, `favorites`, `bookings`, RLS-политики и bucket для фото.
3. Project Settings → API — скопируйте **Project URL** и **anon public key**.
4. Скопируйте `.env.example` в `.env` и вставьте туда эти значения:
   ```
   VITE_SUPABASE_URL=https://xxxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
   ```
5. Задеплойте Edge Function, которая проверяет вход через Telegram:
   ```bash
   npx supabase login
   npx supabase link --project-ref xxxxx
   npx supabase functions deploy telegram-link
   npx supabase secrets set TELEGRAM_BOT_TOKEN=123456:ваш-токен-от-BotFather
   ```
6. Дальше нужно поэтапно переключить `src/lib/repo.ts` с моков на реальные запросы к Supabase (`supabase.from("listings").select(...)` вместо `CITY_RAILS`), и вызывать `linkTelegramProfile()` из `src/lib/auth.ts` в момент подтверждения gate-модалки (`confirmGate` в `src/store/appStore.ts`). Схема и функция для этого уже готовы — это можно делать постепенно, экран за экраном, не ломая то, что уже работает на моках.

## Почему именно такой стек

- **React + Vite + TypeScript** — стандартный способ делать Telegram Mini Apps: это обычный веб-сайт, который Telegram открывает в собственном окне (WebView) и даёт доступ к `window.Telegram.WebApp` (имя пользователя, тема, кнопки интерфейса и т.д.).
- **Supabase** — тот же выбор, что и в вашем проекте PitCrew: Postgres-база, авторизация, файловое хранилище для фото — всё в одном месте, без необходимости писать отдельный бэкенд-сервер.
